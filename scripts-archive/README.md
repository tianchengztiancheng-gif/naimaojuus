# 调查用的一次性脚本

这些不是工程的一部分，是当初「搞清楚这张卡里有什么」时随手写的。
留在这儿是因为它们记录了每个结论是怎么得出来的 —— 接手时想确认某个数据
到底长什么样，照着改改路径就能跑。

跑之前先把角色卡放到 `/home/claude/card.json`（或改脚本里的路径），
需要 jsdom 的那些先 `npm install jsdom`。

| 脚本 | 当初用来查什么 |
|---|---|
| `stat.js` | 每个角色的服装/表情/立绘/差分数量，立绘清单就是它生成的 |
| `stat2.js` | 工程整体统计：世界书条数、场景数、手机资源、各模块行数 |
| `roster.py` | 把 stat 的结果渲染成 `docs/立绘清单.md` |
| `sim2.js` | 第一次用 jsdom 跑真页面，验证手机骨架能不能注入 |
| `t2.js` `t4.js` | 手机交互：群聊新建、筛选三态、表情包面板、分级返回 |
| `t3.js` | 剧情回顾的按轮折叠 |
| `t5.js` | 内置世界书规则是否装入、人设是否进请求 |
| `t6.js` | 每个 App 的回主屏按钮、`.cw` 是否在网格里、13 个立绘特效 |
| `t7.js` | 推荐流改横条后的结构、正文标记渲染 |
| `t8.js` | 设置工作台换皮后的分区/分组/详情表单 |
| `t9.js` | 「点设置跳到启动面板」那个 bug 的复现与验证 |
| `ta.js` | 私聊/群聊分段切换、电量 API、主屏布局 |
| `tb.js` | 统计磁贴、变量页概览卡、磁贴数与筛选是否一致 |
| `tc.js` | 舰娘档案卡、选项只填不发、设置底色权重 |
| `td.js` | **手机独立生成**：用假 API 跑完整往返，验证不污染主线 |
| `te.js` | 连点推进是否丢句/卡死（并发令牌那个 bug） |
| `tf.js` | 连续三轮对话，验证 busy/转圈正常复位 |
| `tg.js` | 表情包在 DOM 里的 src 是否正确、提示词里有什么 |
| `th.js` | `quietContext` 捞到的是人设还是差分名单 |
| `tk.js` | 换装面板：缩略图、锁定、解锁 |

真正长期维护的测试是 `tools/smoke-test.js`（144 项），改完代码先跑那个。
