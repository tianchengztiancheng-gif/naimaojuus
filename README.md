# Gal 引擎 v5.21 · 可玩版

独立运行的角色卡前端。不依赖 SillyTavern，不需要安装任何东西，
双击 `index.html` 就能跑；传到 GitHub 就有网址，手机也能玩。

---

## 快速上手（本地）

1. 解压到任意文件夹
2. 双击 **`index.html`**
3. 按面板上的三步走：载入素材 → 填接口 → 开始

> 首次打开是空的，需要你提供**角色卡 JSON** 和**预设 JSON**。
> 这两个文件只存在你自己浏览器的 IndexedDB 里，不会上传到任何地方，
> 下次打开自动恢复，不用重复导入。

> **仓库里只有引擎，不含任何角色卡和立绘素材 —— 但你不需要额外准备素材。**
> 立绘表、场景表、手机通讯录本来就长在角色卡里，载卡时引擎会当场把它们读出来
> （`core/cardres.js`）。所以干净克隆下来，载入你自己的卡，立绘和背景直接就有。
> 控制台里那几条 `resource/juus/*` 的 404 可以忽略，那是可选的预置素材包。

### 填接口

| 你的情况 | 协议 | API 地址 | 模型 |
|---|---|---|---|
| Anthropic 官方 | Anthropic | `https://api.anthropic.com` | `claude-sonnet-4-5` |
| OpenAI 官方 | OpenAI 兼容 | `https://api.openai.com` | `gpt-4o` |
| 第三方中转 / 本地反代 | 看它文档，多数是 OpenAI 兼容 | 它给的地址 | 它支持的模型名 |
| Gemini | Gemini | `https://generativelanguage.googleapis.com` | `gemini-2.0-flash` |

地址填根地址就行，`/v1`、`/chat/completions` 这些会自动补；
你填完整地址它也认，不会重复拼接。

填完点 **测试连接**。通了会显示延迟和模型的回复，不通会告诉你大概是哪一环：

- `401 / 403` → 密钥无效或没权限
- `404` → 地址不对，试试加上或去掉 `/v1`
- `429` → 触发限流，等一会儿
- 浏览器控制台报 CORS → 这个端点不允许浏览器直连，得走中转

## 挂到 GitHub（拿网址，手机可玩）

1. github.com 右上角 **+** → **New repository**，名字随便起，选 **Public**，Create
2. 仓库页 **Add file → Upload files**，把解压后**文件夹里的东西**全拖进去
   （注意是里面的内容，不是外层文件夹本身 —— `index.html` 必须在仓库最外层）
3. 拖完往下滚，点绿色 **Commit changes**
4. **Settings → Pages** → Source 选 `Deploy from a branch` → 分支 `main`、目录 `/ (root)` → Save
5. 等一两分钟，回到 Settings → Pages 刷新，顶部出现网址：
   `你的用户名.github.io/仓库名`

以后改文件，还是 Upload files 传同名文件覆盖，一分钟后网址自动更新。

**注意**：免费版 Pages 只能用公开仓库。引擎本身是 MIT，公开没问题；
但**别把角色卡、预设和 `resource/juus/` 一起传上去** —— 那些是别人的作品。
`.gitignore` 已经挡住了它们，用 git 推送时不会误传；
用网页 Upload files 手动拖文件的话得自己注意。

不传素材**不影响玩**：网址打开后在开场引导里载入你自己的角色卡，
立绘和背景会从卡里读出来。卡存在你自己浏览器的 IndexedDB 里，不会上传，
所以公开的网址上也没有别人的作品。

## 换一张卡怎么办

引擎本身不认识具体是哪张卡，换卡只要换素材表：

```bash
python3 tools/build-juus.py 新卡.json resource
```

它会从卡的 `regex_scripts` 里找 `EXPRESSION_MAP` / `SCENE_MAP` 并生成
`resource/juus/`。如果新卡的立绘表结构不同，改这个脚本比改引擎容易得多。

加皮肤改 `tools/build-tianqing.py` 里的 `OUTFIT_PREFIXES`，加一行前缀名重跑。

## v5.21 · 预设正则 / 预设生效 / 测试连接拉模型

### 预设自带的正则现在会生效（思维链不再漏出来）

酒馆预设常自带正则（`extensions.regex_scripts`），最典型的是「隐藏思维链」。
以前只复制了预设的提示词块、没接它的正则，思维链整段漏进台词，还每轮原样发回给模型。

新增 `core/regex.js`，按酒馆的语义跑：`placement`（输入 / 输出）、`markdownOnly` / `promptOnly`、
`minDepth` / `maxDepth`、`trimStrings`、`{{match}}` 和 `$1`。
预设里的正则载入预设时自动读取；酒馆里单独导出的正则 json 可以在「素材」一步的 **正则（可选）** 导入（可多选）。
「设置 · 预设」最下面有个 **正则** 分组，每条都能单独开关，也写着它作用在哪、为什么被跳过。

舞台不渲染 HTML，所以替换成 `<details>` 折叠块的当作隐藏，替换成其它 HTML 美化的只在提示词里生效。

不靠预设也有一层兜底：`<think>` `<thinking>` `<cot>` `<思考>` `xxx_cot` 等常见标签一律先剥掉；
只有闭合标签（开头被中转吃了）、或写了开头没闭合（被截断）也能接住。
历史里存的是剥掉思维链的版本，旧推理不再每轮重发。

### 预设「没效果」、一到感情戏就截断

查下来是四件事叠在一起：

1. **后置 system 被拎到了最前面。** 三种协议都把全部 system 消息合并到开头，
   可预设的破限、后置指令、深度注入都是故意放在历史**之后**的 —— 挪到最前面就被几十轮对话压在底下。
   现在只有开头连续的 system 进系统提示词，之后的原地改成 user（酒馆对 Claude / Gemini 也这么做）。
2. **宏没展开。** 以前只认 `{{char}}` `{{user}}` 等四个，预设里的 `{{setvar::}}` / `{{getvar::}}` 开关、
   `{{// 注释}}`、`{{trim}}`、`{{random::}}` 全是原样发出去的。现在按酒馆的顺序求值（最内层优先、从左到右）。
3. **Claude 预设的「助手预填」（`assistant_prefill`）没发。** 现在 Anthropic 协议下作为最后一条 assistant 发出。
4. **Gemini 默认安全阈值会把成人感情戏半路掐断**（`finishReason: SAFETY`）。现在和酒馆一样全部 `BLOCK_NONE`。

另外：深度注入改成按「对话历史」数深度（以前从整条 messages 末尾数，后面有破限块时位置就错了）；
默认最大输出从 4096 调到 8192（先写思维链的预设 4096 不够，看起来就像被截断）。

**每轮结束会告诉你是怎么停的**：到了最大输出、被上游过滤、或者只写了思维链就停了，
都会在顶部弹一条提示，说清楚是哪一环、该调什么。中转自己加的审核这里管不了，提示里也会直说。

### 测试连接：不用先填模型名，点一下就列出全部可用模型

以前「测试连接」必须先填模型名才测得了，而「拉取」用的 `<datalist>` 在模型框有字时只显示匹配项、
手机上干脆不弹，看起来就是「拉了但什么都没有」。另外 Gemini 的测试一直用流式地址去读非流式 JSON，永远测不通。

现在点 **测试连接**：先拉这个接口的全部模型，放进一个真正的下拉框；选一个再点一次，真发一句话验证能对话。
地址填完整的 `…/v1/chat/completions` 也能推出模型列表地址；Gemini 只列能对话的模型。
中转无视 `stream:false` 回 SSE 的情况也兼容了。

测试：`node tools/unit/test-preset.mjs`（71 项），冒烟测试新增 [7b] [7c]。

### 重roll / 撤回 / 存档树

有人反馈「对 AI 回复不满意，不知道怎么重来」—— 以前确实没有入口，只能读档，而存档又藏在 手机 → 设置 里。

**输入框旁边**现在有三样：

- **⟳ 重roll** —— 撤掉最后一轮，用同一句话重新生成。会附一句「换一种写法，别复用上一版」的要求（只对这一次请求有效）。
  没成功（断网、被拦）会把原来那一版放回去，不会两头落空。
- **↶ 撤回** —— 撤掉最后一轮，那句话放回输入框，改完再发。可以连续撤几轮。
- **‹ 2/3 ›** —— 同一轮重roll 过的几版之间来回切，**不发请求、不花钱**。切回去连 CG 和变量一起回去。

撤一轮 = 恢复这一轮开始前的变量、宏变量，再把这一轮的历史和剧情记录摘掉（手机群聊后来加的记录不动）。
这一轮还在出的 CG 会被取消；已经在路上的图不会挂到新版本的句子上。

**存档**改成了存档树（思路和版式参考 KaiTuoYiShi 的「存档树控制台」），右上角 **▤** 直接打开：

- 一个开局 = 一棵树。开场是树根，**每一轮结束自动存一个节点**，每棵树保留最近 8 个自动节点；手动存的不限、不会被清。
- **读一个旧节点接着玩，会从那里长出新分支**，原来那条线还在。界面上标「分支」「当前」「最新」。
- 标签：全部 / 手动 / 自动 / 导入；每个节点显示第几轮、地点、时间、大小、最后一句台词。可以读取、导出、改名（手动）、删除；
  也能整棵树导出 / 删除。删中间的节点，它下面的节点会改挂到上一级，树不会断。
- 重roll / 换版本写回同一轮的节点，不会一版一个地堆；读档后照样能重roll。
- 存档另存一份「目录」摘要，打开列表不用把每份存档完整读出来（以前每份都要整份读，大的好几 MB）。
- 浏览器不支持 IndexedDB、降级到 localStorage 时（5MB），不存每轮节点，只留「最新进度」和手动存档，免得撑爆。

顺带修了一个老 bug：勾了「连 CG 图一起导」导出、或者导入带图的备份，会报 `global is not defined` —— app.js 里写成了 Node 的 `global`。

测试：`node tools/unit/test-savetree.mjs`（25 项）、冒烟 [7d]、`node tools/e2e-reroll.mjs`（Playwright 真跑：重roll → 翻版本 → 撤回 → 读旧节点长分支 → 手动存档 → 删中间节点 → 手机宽度）。

### 对照开拓轶事（KaiTuoYiShi）补的漏洞

拿 [KaiTuoYiShi](https://github.com/LingYuYue1/KaiTuoYiShi) 这个成熟的脱离酒馆前端逐项对了一遍预设、正则、测试连接、破限相关的实现。
补上的（都是我们原来没有、它有的）：

| 方面 | 原来的漏洞 | 现在 |
|---|---|---|
| 预设 | `prompt_order` 一律取第 0 组。酒馆导出常有 100000（旧残留）和 100001（实际在用）两组，取错就是**开关和顺序全是旧的** | 优先 100001，其次条目最多的一组；编辑器同步 |
| 预设 | 块正文只认 `content` | `prompt` 字段也认；`chatHistory` 等占位只出现在 prompt_order 里也认 |
| 预设 | `injection_trigger` 不看，只在「续写 / 重roll」时该发的块每轮都发 | 普通一轮只发空触发或含 `normal` 的块 |
| 预设 | 预设附带的 `world_info` 丢了；独立导入的世界书位置 / 深度 / 顺序 / 禁用也丢了 | 进世界书，换预设时替换；平铺格式字段都读 |
| 预设 | 带 BOM、尾逗号、包了 \`\`\`json 的文件直接「解析失败」 | 宽松解析 |
| 宏 | 没有 `{{if}}` / `{{else}}`、`{{.变量}}` / `{{$变量}}` 简写、`{{trim::}}` 等 | 都有。而且 `{{if}}` 只执行被选中的分支（KT 的实现会把假分支里的 setvar 也执行掉） |
| 正则 | 只认 `extensions.regex_scripts` 的驼峰字段数组 | 也认对象映射、snake_case、SPreset 正则绑定等位置；`substituteRegex` |
| 正则 | 预设的抗空回 `<Q>…</WF>`、抗截断 `<math>…</math>` 占位没清理规则就演进台词 | 兜底删掉（注释只在显示里删，给模型看的历史保留） |
| 正则 | 看不出一条正则到底干了什么 | 设置 · 预设 · 正则，点一条可以贴模型原文**试跑** |
| 测试连接 | 回个「ok」就算通 —— 中转回缓存、换了模型也看不出来 | 让模型复述**随机校验码**，照抄了才算真通 |
| 测试连接 | 模型列表只试一个地址 | `/v1/models`、`/models` 等依次试；401 直接报密钥问题 |
| 接口 | `/api/v3`（火山方舟）、`/beta` 会被错补成 `/api/v3/v1/…` | 带版本段的不再补 `/v1` |
| 接口 | content 是分段数组、包了 `data`、OpenAI 地址回 Anthropic 格式 / Responses 格式，都读不出正文 | 都能读，思考分段一律不进正文 |
| 接口 | 参数不兼容直接 400：推理模型不收 `temperature` / 要 `max_completion_tokens`，小模型输出上限 4096，新一代 Claude 不收预填 | 认出是哪个参数，自动去掉 / 调小再发，并记住；顶部提示调了什么 |
| 破限 | 助手预填只在 Anthropic 协议发 | DeepSeek 官方走前缀续写；「助手预填」可选所有接口都发 |
| 破限 | 空回复只能手动重发 | 空回（或剥完思维链、占位块后什么都不剩）自动再要一次；写思维链写到上限的不白白重试 |
| 接口 | 没有酒馆的「提示词后处理」 | 「消息后处理」：自动 / 保留 system / 全部合成一条 |

**我们本来就比它做得好的，没动：** 预设深度注入按对话历史定位（KT 的酒馆消息链不处理 `injection_position=1`）；
中途 system 原地改 user（KT 对 Claude / Gemini 仍把全部 system 拎到最前）；Gemini 安全阈值放开（KT 没发 `safetySettings`）；
正则按酒馆语义真正执行 promptOnly / markdownOnly / 深度（KT 默认只执行安全清理类，其余只展示）。

**没搬的：** 它的「Claude 兼容」模式会伪装成 Claude Code 客户端发请求头，没搬；
COT 伪装三连、本回合核对块这些是跟它自己的输出协议绑死的，我们用的是玩家自己的预设，不适用；
火山方舟 / 千帆等需要它自己服务端代理的接口，我们是纯静态页面，接不了。

测试：`node tools/unit/test-kt-parity.mjs`（58 项）。

## v5.20 · 开场引导 / 文生图 / CG / 真实分词 / 语义检索

### 开场引导

打开就是一个四步向导，不再是一长条表单：**① 素材 → ② 接口 → ③ 插画（可选）→ ④ 开场**。
左栏是步骤导轨，每步齐了会亮绿点；右栏是 `STEP 01 / ASSET` 的抬头加进度条。
最后一步给一张「齐没齐」的清单，哪一项缺、缺在第几步，一眼能看到 ——
比只给一个灰按钮清楚。有自动存档时左上角会出现「继续上次」。

版式借鉴天青的标题画面（满幅背景 + 左侧竖排菜单）和开拓轶事的新游戏向导
（步骤导轨 + STEP 编号 + 进度条），配色是我们自己的碧蓝。
**背景全是 CSS 画的**（渐变 + 三层缓慢横移的波纹 + 网格），
不引任何图片，离线打开一样好看，也不多一个字节的下载。
窄屏下导轨自动收成顶部标签条。

四件大事。全部**默认关闭** —— 打开前不会多花你一分钱、一个 token。

### 文生图，并且让它接管 CG

原来 CG 要手工准备素材表；现在 **CG 就是这一轮现生成的图**，剧情走到哪画到哪。

后端目前只接 **NovelAI**（`core/imagegen.js`）。移植自开拓轶事的出图服务层 ——
天青自己不会出图，它的「🎨 生成」是调酒馆的 `/imagine`，我们没有酒馆兜底，
这一层必须自己写。搬过来的包括：模型档案与官方推荐参数、V4/V4.5 的
`v4_prompt` 多角色分段与站位、手写 ZIP 解包（NAI 回的是 zip 不是 png，
用浏览器内置的 `DecompressionStream`，**零依赖**）、按错误类型分级的提示。

**默认尺寸 1216×832** 是挑过的：横画幅适合当 CG，而且 1,011,712 像素压在
1,048,576 那条线以下，配 23 步正好落在 Opus 会员的**免费档**里。
设置页会实时算给你看当前参数是「✓ 免费档」还是「⚠ 会扣点数」。

出图**全程异步**，不挡剧情：先演，图十几秒后到，到了自动补上，翻回去也在。
一张图 1~2MB，所以图存 IndexedDB，**存档里只存 id** —— 直接塞存档几轮就废了。
超 200 张淘汰最旧的，收藏（★）的永不淘汰。

### 私信是发给指挥官的，舰娘之间说话走群聊

`[短信|角色名|文字|内容]` 的收件人**永远是指挥官**。但模型很爱拿它写舰娘之间的对话，
结果就是 Z52 和 Z9 在互相说话，两条却各自躺在「和指挥官的私聊」里，
指挥官被莫名其妙地夹在中间。

两道防线：世界书那条手机规则现在写了正反例，明确「说话对象是指挥官 → 短信；
说话对象是别的舰娘 → 群聊」；引擎这边也拦一道 —— 认出「这条其实是说给别的舰娘听的」
就改投到「舰娘闲聊」群里。

怎么认：开头喊了别人的名字（`Z9！！！你看到了吗`），或者把指挥官当第三人称提
（`Z47坐在指挥官大腿上了` —— 真给指挥官发消息会说「你」）。
判断是**按「发信人 + 本轮」整组**做的：一组里只要有一条露馅，整组都跟着走 ——
「别转移话题！」这种单看毫无线索，但它和前一句是同一段对话，不能一半在私聊一半在群里。

### 提示词默认不额外花钱

打开文生图的开关时，世界书里那条「【引擎】插画输出规则」会**自动启用**。
它是持久指令，让 AI 每轮自己产出 1~2 段 `<image>`，引擎直接拿来出图 ——
不额外发请求。某轮 AI 忘了写，才退回「另发一次请求解析正文」兜底。

格式参考了油猴世界书那套（`Character N Prompt` / `Character N UC` 成对、
`|centers:x,y` 站位、`source#`/`target#` 标明谁主动谁被动），
那套在实战里跑通过，比自己拍的稳。

### CG 怎么显示

工具栏上的 **▣** 是个**只有两种状态**的开关，没有中间态：

- **开（默认）· CG 模式** —— CG 盖住立绘，一旦铺上就**留到被下一张换掉为止**，
  你可以就这么推剧情。点 CG 图本身也能推进。
- **关 · 立绘模式** —— 舞台上**完全不出 CG**，要看图去相册（✿）。

之前把「关」做成了「只在图所在那一句显示」，结果关掉也照样时不时盖上来，
按钮等于没用。二选一才说得清。

### 换装：点了就锁定

- **关** —— 只换当前这一句，下一轮恢复自动。

### 重画

出得不满意可以重来，三个入口：

- CG 图右上角的 **♻**
- 相册里每张图的 **♻**
- 相册顶部那条 —— 它会显示你当前停在哪一句、有没有图。**没有图的句子也能补一张**

重画时用的是**整轮**的正文当上下文，不是孤零零那一句 —— 一句「嗯。」解析不出画面，
而且生成时本来就是按整轮解析的，重画保持一致才不会出来两种画风。

旧图会被删掉，但**收藏（★）过的不删** —— 点了 ★ 就是明确说「这张要留着」，
重画只换掉这一句挂的图，不该顺手毁掉收藏。

### 提示词从哪来：两段式 vs 内联

| 模式 | 怎么工作 | 代价 |
|---|---|---|
| **两段式**（默认） | 另发一次请求，把正文解析成结构化的出图提示词 | 每轮多一次请求 |
| 自动 | 模型写了 `<image>` 就用，没写才解析 | 看模型配合度 |
| 内联 | 只认模型写的 `<image>`，绝不额外发请求 | 最省，质量最不稳 |

两段式做了一处省钱设计：**每轮 2 张图只解析一次**。Schema 用 `shots` 数组
一次返回多个镜头，而不是一张图一次请求。

解析走的是 `engine.quiet()` —— 手机私聊那条独立通道，它本来就带世界书激活的
人设和最近剧情，白捡一份上下文。解析失败会退回本地草稿，整条链路不会断。

内联模式需要打开内置世界书条目「【引擎】插画输出规则」（默认关着，
切模式时会自动开关它）。

⚠ `<image>` 块必须写在**正文之外**，引擎也在切分事件流**之前**整块抠掉它 ——
天青在这里栽过两次：块里的 `Character 1 Prompt:…|centers:c3` 含 `|`，
而剧本行正是用 `|` 分段的，不先摘掉会被切成一串假台词。

### token 真实分词

原来的粗估是「CJK 1 字 1 token，其余 4 字符 1 token」。实测
（跑 `node tools/measure-tokens.mjs` 可复现，不要信这张表，自己跑一遍）：

| 样本 | 字符 | 粗估 | cl100k | 误差 | o200k | 误差 |
|---|---:|---:|---:|---:|---:|---:|
| 纯中文（无标点） | 28 | 28 | 35 | −20% | 23 | **+22%** |
| 带标点对白 | 21 | 17 | 30 | **−43%** | 22 | −23% |
| 剧本行 `她抬起头。\|柴郡\|微笑\|` | 12 | 9 | 16 | **−44%** | 14 | −36% |
| 世界书人设 | 149 | 131 | 207 | −37% | 141 | −7% |
| JSON 变量 | 46 | 26 | 33 | −21% | 28 | −7% |
| 英文 prompt | 122 | 31 | 30 | +3% | 30 | +3% |
| **合计** | | **242** | **351** | **−31.1%** | **258** | **−6.2%** |

以 cl100k 为准，粗估整体低 **31%**，最坏的剧本行低 **44%**。而世界书的预算裁剪就是按
这个数裁的 —— 低估等于「以为还有空间」，实际发超。juus 是大卡，偏差会被放大。
换成 o200k 这套更大的词表，粗估只低 6%，可见「差多少」高度依赖你实际用的是哪个模型。

接的是 gpt-tokenizer 2.9.0（MIT，Bazyli Brzoska，npm 官方 UMD 构建），按模型名选
`cl100k_base` / `o200k_base`，**用到时才加载**那 1~2MB 的脚本。世界书预算多了
「按真实 token 裁」的选项，默认仍是按字符，不动既有手感。

三条限制在界面上也写着：

- 这是 OpenAI 的分词器，对 **Claude / Gemini 是估算**，它们的分词器不公开，拿不到真值。
- **认不出的模型默认按 o200k 算**。这是一个判断，不是实测结论：cl100k 是 2022 年的
  10 万词表，对中文切得极碎；Claude / Gemini / 国产模型用的都是更大的现代词表。
  但没有公开数据能证实，你手上要是有真实用量账单，以账单为准。
- 嫌包大可以直接删掉 `core/vendor/gpt-tokenizer-*.js`（合计 3MB），会自动回退粗估，不报错。

> **勘误。** v5.20 的文档里这张表登过两版错的数：先写「整体低 11%」，又说「纯中文是高
> 估的」。原因是我当时用的 `gpt-tokenizer-cl100k_base.js` 是从 Larimar 的 vendor/ 拿的，
> 而那个文件里装的其实是 **o200k 的数据**（它和同目录的 o200k 文件对同一段中文给出完全
> 相同的结果，npm 官方的两个文件则不同）。换成 npm 官方构建重测才是上表。现在两个
> vendor 文件都来自 npm 2.9.0，测量脚本也一并放进 `tools/`，省得再出这种事。

### 世界书语义检索

关键词激活是**字面**命中：条目写了「甜品厅」，正文里得真出现这三个字。
玩家说「想吃点甜的」一个词都不沾，那条就捞不上来。

现在可以按语义补捞。走你已经配好的那个端点的 `/v1/embeddings` ——
浏览器内嵌 embedding 模型要下几十 MB 权重，对「双击就能玩」的项目太重了。
建索引是**一次性**的（166 条各算一次，按内容哈希缓存，改了才重算），
每轮只多一次「把当前这句转成向量」的极小请求。

很多中转只转发对话接口、不转嵌入接口 —— 那样会**自动退回纯关键词**，
不报错、不挡路。

配套做了**时间衰减**：最近几轮注入过的条目降权，免得同几条反复霸占预算。
刚注入过 ×0.55，隔 3 轮 ×0.78，隔 6 轮完全恢复。蓝灯常驻不参与。

⚠ 这一层只**追加**，永远不会挤掉关键词已经命中的条目 ——
关键词是作者写死的意图，语义相似只是补充。

### 没说话的人也在动

```
[ { "op": "replace", "path": "/地点", "value": "重樱神社" },
  { "op": "delta",   "path": "/人物/柴郡/好感度", "value": 8 },
  { "op": "insert",  "path": "/人物/雅努斯", "value": {…} },
  { "op": "remove",  "path": "/人物/柴郡/服装" } ]
</JSONPatch>
</UpdateVariable>
```

我写的解析器找的是 `_.set('路径', 值)` —— 完全对不上，所以一条都没解析成功，
地点、好感度、在场状态全程原地不动。

现在实现了完整的 JSON Patch：`replace` / `delta` / `insert` / `remove` / `move`，
JSON Pointer 路径（含 `~0` `~1` 转义和数组 `-` 追加），
模型把数字写成字符串也会自动转。旧的 `_.set()` 写法继续兼容，
并且认 MVU 那种 `_.set(路径, 旧值, 新值)` 的三参数形式。
JSON 有尾逗号或注释时会清一遍再解析。

这条修好之后，地点、好感度、服装、在场状态、新角色加入全都会跟着走了。

## v5.12 修了什么

### 有几句不显示 / 某句直接卡死
同一个根因：`present()` **没有并发令牌**。这个守卫是我加「回看」功能重写它时弄丢的。

连点推进时，上一句的立绘可能比这一句晚加载完，它的回调落在后面，
于是把新句子的文字**盖回成旧的**（表现为"有几句没显示"），
同时把 `typing` 重新置 `true` —— 之后你再怎么点，`advance()` 都只走
"打字中→补全"这条分支，永远推不动，看起来就是死在那句了。

修法是给每次 `present()` 发一个递增令牌，回调和打字机每一帧都校验；
令牌过期就直接退出，不碰界面、不改 `typing`。

### 顺带三处
- **立绘等待上限从 3.5 秒压到 400ms**。之前图没缓存时对话框会空一秒多，
  这本身就是"这句没显示"的观感来源。现在立绘晚到就自己淡入，不再拖住台词。
- **选项不再挡住推进**。`advance()` 里有一句 `if (!choicesEl.hidden) return;`，
  那是选项会直接提交时的写法；现在选项只填输入框，这个拦截就成了纯粹的卡顿源。
- 单张立绘的加载兜底也从 3.5 秒压到 1.5 秒。

### 验证
用假 API 跑了连续三轮：日志 2→4→6 句、进度和文字始终对应、
API 恰好调用 3 次、发送按钮和转圈都正常复位。
另外模拟连点 6 次 + 再点 3 次，进度一路走到 8/8，文字与进度同步。

- **OpenAI 兼容路径没做角色规整** —— 开场白以 `assistant` 身份进历史，
  于是每次请求都是 `system → assistant → user`。clewdr 这类中转后面接的是
  Anthropic，那边要求首条非 system 必须是 `user`。现在两条路径都会规整：
  合并连续同角色、首条是 assistant 时补一条占位 user（**不丢开场白**）。
- **断线不再直接失败** —— 网络类错误自动重试 2 次（退避 1s / 3s），
  转圈上会显示「断线重连 1/2」。密钥错、地址错这类不会重试。
- **报错带上请求规模** —— 顺便告诉你这次发了多少 token，便于判断是不是太大。
- **兜底告警改成人话** —— 不再显示 `other-period` 这种术语，
  按「无妨 / 将就 / 明显不对」分三级，每条说明具体发生了什么。

## v3.2 修了什么

- **转圈不消失 / 选项点了没反应 / 存读档关不掉** —— 同一个根因：
  `hidden` 属性靠浏览器默认样式 `[hidden]{display:none}` 生效，
  但我给这些元素写了显式 `display:flex`，作者样式压过默认样式，
  于是 `el.hidden = true` 对转圈、选项、两个侧栏全部失效。
  加一行 `[hidden]{display:none!important}` 兜住。
- **请求可能永远挂住** —— 流式连接偶尔不返回，加了 3 分钟超时和「中断」按钮，
  转圈上会显示已等待秒数。已收到部分内容时中断，按部分成功处理，不丢。
- **上一轮没回来时点选项会被静默吞掉** —— 现在会把选项文字填进输入框，
  等这轮结束你直接回车即可。

## v3.1 修了什么

- **背景全程空白** —— juus 的剧本把地点写在 `『✨ 日期 · 星期 · 时刻 · 地点 · 天气 ✨』`
  抬头里，引擎原来只认 `<背景|>` 标签，所以永远拿不到地点。现在会解析抬头，
  而且不按固定下标取段，是让每一段去场景表里试，挑匹配最好的当地点 ——
  别的卡抬头格式不一样也能用。时刻会换算成时段（08:12 → 朝）。
- **立绘太大、下半身被对话框挡住** —— 加了「↕ 立绘微调」浮层，
  可以调大小（45%~130%）和垂直位置，实时生效并记住。默认从 100% 调成了 78%。
- **存读档面板空白且没反应** —— `file://` 下部分浏览器禁用 IndexedDB。
  现在有三级降级（IndexedDB → localStorage → 内存），降级时面板顶部会说明当前用的哪种。
- **`<update>` 改的地点被剧本抬头覆盖** —— 现在 update 优先，
  它表示回合结束时的位置，抬头只描述本轮画面。

## 已知限制

- **世界书检索是实用子集**，不是酒馆的逐位复刻。蓝灯绿灯、主次关键词四种逻辑、
  概率、order、七个插入位置、深度注入、递归、预算裁剪都有；
  v5.20 又补了向量化语义检索和时间衰减（默认关，要填 embedding 接口）。
  所以同一句话可能触发的条目和酒馆里仍不完全一样。
- **token 计数对非 OpenAI 模型仍是估算**。v5.20 接了真实 BPE（gpt-tokenizer），
  对 GPT 系是精确值；Claude / Gemini 的分词器不公开，只能拿 o200k 近似
  —— 比粗估准得多，但不是真值，别拿它当账单。粗估兜底仍在（删掉 vendor 那两个
  文件就回退），实测误差见上面「token 真实分词」那一节。
- **卡自带的正则只收短脚本**。几十万字的 HTML 渲染器会跳过 —— 我们有自己的渲染器，
  把那种东西塞进文本流只会把剧本冲掉。同时脚本自身的启用状态会被尊重：
  juus 卡 19 条正则里 15 条本来就是禁用的。
- **小手机没接**。它是独立的 TavernHelper 脚本，靠扫描聊天记录里的标签生成内容，
  接进来需要另写一层适配。
- **模型输出会比样例脏**。七个官方开局能做到 97% 精确命中，
  实战大概率更低 —— 调试面板的兜底告警就是给这个用的。
